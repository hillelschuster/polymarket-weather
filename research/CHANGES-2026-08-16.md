## Era 3 — 2026-08-16 ~06:40 UTC: settlement/margin honesty (supervisor v3)

1. **BUGFIX settle timing**: settling at `endDate+3h` used PARTIAL-day station data for
   US/EU high markets (their local day ends hours after endDate). Fix: settle when
   `local_day_end_utc + 2h` (from target date + city offset). Revert: restore
   `settle_when = end + timedelta(hours=3)`.
2. **US °F margin 2.0 -> 3.6**: 2.0 in °F units was only 1.1C real margin; METAR whole-C
   quantization (±0.9F) ate it. Revert: single `margin = 2.0`.
3. **Paper fill honesty**: shares capped at 90% of displayed top-of-book depth
   (`mk()` in `detectors`); detections with <5 shares dropped (CLOB min order).
   Revert: `shares = int(want)`.
4. `top_of_book` now stores `tokens` + `yes_idx` (outcomes-aware) in each row for the trader.

## Era 4 — 2026-08-16 ~19:15 UTC: side inversion + running-extremum (supervisor v4)

1. **BUGFIX settle side inversion (CRITICAL)**: scorer paid NO positions when the bucket
   HIT (backwards). Fix: `pos_won = bucket_hit if side=="YES" else not bucket_hit`.
   8 mis-settled closures deleted and re-settled; re-sent positions tagged
   `"era": "pre_running_state"` in pending. True era-1-3 R3 record: 1W/6L (family was
   losing; see 2).
2. **BUGFIX current-obs anchoring (CRITICAL)**: tropical post-shower temp drops made
   already-achieved peak buckets look "dead above" (Singapore/Taipei/Guangzhou losses).
   Fix: `fetch_running()` — up to 14h of recent METARs filtered to the event's local
   calendar day -> `(runmax, runmin)` per station. R3 anchors on running MAX, R2 on
   running MIN, R1 requires running-min AND current obs inside the bucket.
   Revert: detectors signature back to obs-only anchors.
3. **NEW R4 high-side lotto**: symmetric to R1 — running daily max inside bucket,
   ask <= 0.02, window `[lastlight-2.5, lastlight]`, q floor 0.15, size $2.
   Revert: delete the R4 block in `detectors()`.

## Era 7 — 2026-08-17 ~05:30 UTC: lotto sweep execution (live_trader v2)

User-approved. Problem: trader sized off top-of-book only (HK case: captured 9 of 2,009
available shares -> $9 instead of ~$2,000), and lotto rules were not whitelisted at all.
Change:
1. R1/R4 lotto rules whitelisted for auto-execution (they fire only at asks <= 0.002 per
   supervisor v5 tier).

   (0.002), taking 90% of each level, bounded by LOTTO_SWEEP_CAP ($ default 5, env

   tier limit walks all levels atomically.

Revert: git revert this commit (returns to R2/R3-only, top-of-book sizing).
Note: supervisor paper accounting stays $2/top-level conservative on purpose — paper
measures P(win|state) calibration; the trader measures dollar capture. Divergence is
intended and visible in live_orders.jsonl.
